## Known limits (read before you copy this setup)

1. HDD rollback kernel on both consoles is the original crashnt-4.7 build
   (f0008d466329d07d456fda63fe03129f7af0403a4040d357d3a62658e3d17293), which predates the pidfs fix.
   The pidfs-fix build (0bd2726640d571c1c28fad7a721ba7db65e04472adcb7f7674312ecf9d72b289) is on the sticks only.
2. The sticks' default bzImage is the pidfs-fix build, so plugging a stick back in boots that, not jupi-1.0.
3. The initramfs USB fallback finds the root by the `psxitarch` label. JUPI 1's stick matches.
   JUPI 2's stick root is labeled `JUPI2ROOT`, so a JUPI 2 stick boot through that fallback would stop
   at HOLD_NO_USB. The stickless internal path does not use it.
4. `uname -r` stays `6.15.4-crashnt-4.7_no-built-in-fw` on purpose (boot audits compare it).
5. A QEMU boot of the JUPI 1 image recorded on Nov 27 hung 5.7 s in, after `/init` found the virtual
   USB disk's partitions. Cause UNSOURCED. It does not affect the real consoles above.

## Binary and firmware

The kernel config embeds ten MediaTek MT7668 Wi-Fi firmware files (`CONFIG_EXTRA_FIRMWARE`, JUPI 2's
Wi-Fi). Those files are not ours to redistribute, so the bzImage is not published. To rebuild,
supply them from your own `/lib/firmware`. The kernel itself is GPL-2.0; the source base
(feeRnt/ps4-linux-12xx v6.15.4__crashnt-4.7, commit 2dbf2bb3), the four patches and the full config are
in ../kernel/ (portable steps: [REBUILD.md](REBUILD.md)). Sony firmware, payload binaries and jailbreak hosts are not part of this repo.
